The gapWhy this doesn't exist yet

Agents move
money with
no history.

Autonomous agents already execute trades, route payments, and manage budgets. Almost none of them carry a verifiable track record. Every counterparty is taking a blind bet.

No credit history

An agent deployed five minutes ago looks identical to one that's run flawlessly for a year. There's no signal to tell them apart.

Opaque transactions

Protocols and counterparties can't assess risk before extending access. They either trust blindly or block everyone equally.

No consequences

When an agent misbehaves, there's rarely a lasting mark against it. Bad actors can redeploy and blend back in with good ones.

Scoring systemA FICO for agents

One score.
Ten grades.

FORGE computes a 0-1000 score from payment history, credit utilization, age of credit, credit mix and inquiry velocity the same weighted factors a traditional bureau uses, applied to an agent's transaction record. Ten letter grades, AAA down to D, turn that number into an instant, human-readable risk read.

AAA 950-1000

Exceptional track record, highest trust.

AA 900-949

Excellent history, very reliable.

A 850-899

Strong performance, trustworthy.

BBB 750-849

Good standing, investment grade.

BB 650-749

Fair record, room for improvement.

B 550-649

Adequate but limited history.

CCC 450-549

Below average, caution advised.

CC 350-449

Poor record, significant risk.

C 250-349

Very poor, near default.

D 0-249

Default risk, avoid.

For developersShip trust in a few lines

Read a score.
Gate a decision.

One typed client for reading scores, registering agents, and gating actions on trust. Drop it into any agent framework or backend.

import { createForgeClient } from "@forgepay/credit";

const client = createForgeClient({ apiKey });

// Read an agent's dual-mode score
const score = await client.getDualScore(agentId);
console.log(score.mode1); // 967 · AAA · offchain, authoritative
console.log(score.mode2); // 942 · settled on Base, if configured

// Gate a decision before extending credit or access
if (score.mode1.grade === "AAA" || score.mode1.grade === "AA") {
  await client.extendCreditLine(agentId, { terms: "net-30" });
}

InfrastructureWhat it's built on

Two scores.
One decision.

FORGE Credit computes every score twice, from two different sources, and shows both. Mode 1 is always authoritative; Mode 2 is the check.

Mode 1 · FORGE FICO

The lending decision. Computed off-chain from payment history, utilization, credit age, mix and inquiry velocity the same factor weighting a traditional bureau uses. Sub-15ms, always available.

Mode 2 · Operational

The behavioral check. Derived from an agent's on-chain activity success rate, volume, budget compliance and settled on Base when a chain client is configured. Absent, not guessed, when it isn't.

Consensus scoring

The two modes are compared on every pull. Agreement is high confidence; a large variance flags the agent for manual review before credit is extended.

DID-based identity

Every agent registers with a decentralized identifier. Identity is checked against the FORGE agent registry, with a documented fallback when that registry can't be reached.

Cryptographic commitments

Report requests can be paired with a signed commitment over the score today; full zero-knowledge selective disclosure so a lender can verify a threshold without seeing the number is in active development.

Stablecoin-native settlement

Credit-line draws and inquiry billing settle in USDC, not card rails or invoices.
