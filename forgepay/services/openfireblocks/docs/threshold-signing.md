# Threshold signing (2-of-3)

Each workspace gets its own secp256k1 key, generated by distributed key generation
(bnb-chain/tss-lib) across the signing nodes. No node, and not the coordinator, ever holds the
whole key. Any `t+1` nodes sign together; the signature is ordinary ECDSA and verifies as the
workspace's address on-chain.

## Components
- `mpc-signer` — coordinator. Holds only an ed25519 key used to sign session requests.
- `mpc-node` — one per share. Peer-to-peer encrypted messages, sealed share at rest, per-node
  value cap, hash-chained audit log (`mpc-node verify-audit`).
- api-gateway — creates a key lazily the first time a workspace needs one (`custody.keys`).

## Environment
| Variable | Where | Meaning |
|---|---|---|
| `MPC_THRESHOLD_SIGNING=true` | gateway | sign with a per-workspace key |
| `MPC_REQUIRED=true` | signer | refuse the legacy shared key |
| `MPC_CLUSTER_FILE` | signer | node list, ids, URLs, public keys, trust domains |
| `MPC_COORDINATOR_KEY_FILE` | signer | coordinator ed25519 key |
| `MPC_NODE_SEAL_KEY` | node | encrypts the share at rest |
| `MPC_NODE_MAX_VALUE_WEI` | node | per-node refusal limit |

`scripts/mpc-dev-cluster.sh <dir>` starts three local nodes on :8101-8103.

## Behaviour
- Fewer than `t+1` reachable nodes: the transfer is not signed, the reason names the quorum, and
  the console offers Retry signing (once, race-safe).
- A node that refuses (value cap, bad request) is not rerouted around.

## Known limits
- The dev cluster is one trust domain. Splitting only helps when nodes run on separate hosts
  under separate control; the console warns while `trust_domains < 2`.
- The seal key sits beside the share in dev; production should use a KMS/Vault.
- No key rotation or resharing. Existing workspaces get a key on first use.
- Nodes' independent policy is a value cap only.
- No broadcast without an RPC configured.
