Scoring Model

event-driven · explainable
  1. 35%Payment success rateconfirmed vs failed transfers from wallet + custody events
  2. 30%Volume consistencyamount variance across trailing 90 days
  3. 20%Compliance recordsanctions screens, policy rejections, chargebacks
  4. 15%Account agetime since did:forge registration

Score changes are event-sourced: each wallet.transaction.confirmed and custody.signature.confirmed ontology event replays into the model, so every score is auditable back to the transactions that produced it.
