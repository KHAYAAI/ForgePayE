# 02 - Asset inventory: secrets, keys, credentials and sensitive data

Evidence base: commit `da11f54`. Path abbreviations are defined in [README.md](README.md). "Reader" means anyone or any
process that can obtain the value without breaking the protection in the "Protection" column. No secret values appear
in this document or in the repository sections cited; where an example or default value is in the code it is named as a
*default* and flagged.

Severity wording in "Blast radius": **funds** = can move or freeze value; **identity** = can act as a person or service;
**data** = confidentiality or integrity of records.

## E. Highest-value combinations an attacker would want

1. `t+1` node hosts (or `t+1` seal keys plus disks) -> a workspace's key. The domain rule and mTLS make this require
   `t+1` separate compromises *only if* the topology is truly separated (domain labels are self-declared,
   `cluster.go:156-163`).
2. `ADMIN_API_KEY` + `OPENFIREBLOCKS_ADMIN_KEY` holder -> all quorum votes and transfers up to node policy.
3. Access to the `mpc-signer` HTTP port -> signing requests within node policy, keygen, reshare (F-01).
4. The stablecoin gateway process or its environment -> payout key, gas key, operating key, all unswept deposit keys
   (via the Vault/KMS role), and the admin keys.
5. Write access to the stablecoin gateway's Postgres -> payouts, sweeps, caps (threat model C).
